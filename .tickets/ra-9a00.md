# Mobile map frontpage: full-screen map with floating controls

On mobile (<=576px) the map frontpage uses the desktop side-by-side layout
(map + pane-body + icon-column flex row). When the pane is open it takes
calc(100% - 60px), squeezing the map to nothing. Mobile users can't see the map
and the side pane at the same time, and the layout is cramped.

Redesign the mobile layout as a full-screen map with the controls
(my-page/login, my position, search) floating over the map as a bottom-right FAB
stack. The side pane and its contents are dropped entirely on mobile: no
nearby-repeaters list and no in-page details panel.

## Design

Mobile (<=576px, pico sm breakpoint):

- Map (#repeater-map-host) fills the full viewport.
- The side pane (#pane-body: header + nearby-repeaters list + details panel) is
  hidden entirely.
- Icon controls (#icon-column) float as a rounded bottom-right FAB stack
  (right-thumb reach) instead of a fixed 60px right strip. The pane-toggle
  button is hidden (no pane to toggle).
- Tapping a map marker navigates straight to the repeater detail page
  (/{call_sign}), since there is no in-page details panel on mobile. Marker
  call-sign tooltips and the search modal remain.
- Desktop (>576px) layout is unchanged (side-by-side flex row with the nearby
  list + details panel). Implementation in templates/pages/map.html CSS + JS,
  switched via a (max-width: 576px) media query and a matching JS matchMedia.
  updateNearestList() is skipped on mobile.

## Acceptance Criteria

- On a narrow viewport the map fills the screen with no side pane and no
  nearby-repeaters list.
- Floating controls (my-page/login, my position, search) are reachable
  bottom-right.
- Tapping a marker opens that repeater's detail page on mobile.
- No horizontal scrolling on small screens.
- Desktop layout (side pane, nearby list, details panel) unchanged.
- docs/design/pages/map.md updated to describe the mobile layout.
- just all, just test pass.

## Notes

**2026-06-11T19:38:10Z**

Design decisions (from review):

1. Viewport: pad the map bottom by the sheet's visible height so
   getBounds()/nearest-list excludes repeaters hidden under the sheet (use
   Leaflet paddingBottomRight on fitBounds and an inset rect for the contains()
   check). Keeps the "pane never covers visible map" invariant.
2. Interaction: tap the handle to cycle peek <-> expanded, CSS-transition
   animated. No finger-drag gesture (avoids Leaflet pan / inner-scroll
   conflicts).
3. Initial state: peek on load.
4. Controls: float as a FAB stack at bottom-right (reachable by a right-handed
   thumb), sitting above the peek sheet, instead of the fixed 60px right strip.
   Sheet handle is a full-width tap target.
